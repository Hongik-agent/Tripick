# ADR 0003 · 서버 저장과 Google Maps로 통일하고 AI 동선 연동을 분리

날짜: 2026-11-15. 상태: 사용자 결정 반영. 2026-11-16 저장 기반·바탕 지도·홈 세계지도 구현, AI·실제 장소/경로 검증은 후속.

## 결정

1. 개인 일정·공개 사본·하트의 영속 저장은 React → FastAPI → PostgreSQL로 통일한다. localStorage와 실패 시 로컬 대체 저장을 제거한다. 브라우저 메모리는 화면 상태·미저장 입력용이다.
2. FastAPI가 세션·소유권·입력·활성 저장 최대 3개·버전 충돌을 검사한다. 2026-11-15 추가 결정으로 이미 3개이면 신규 생성·미저장 결과 재생성을 차단하고 기존 저장 일정 재생성만 허용한다. 결과 확인 후 같은 일정 ID에 재저장한다. 공개 데이터는 허용 필드만 복사하고 날짜·개인 조건·계정 ID·이메일을 공개하지 않는다.
3. 홈 세계지도를 제외한 모든 여행지 결과·저장 상세·게시 상세의 지도는 Google Maps로 통일한다. 국내 네이버·카카오·Google 선택 요구를 대체한다. 로그인 제공자 Kakao 지원과는 별개다.
4. 홈 세계지도에는 React Simple Maps 기반 SVG 세계지도를 추천한다. 설치·버전·지도 데이터는 호환성과 라이선스 검증 후 결정한다.
5. 지도 바탕 표시와 서버 저장 기반을 먼저 구성한다. **OpenAI SDK**로 AI 일정 생성을 연결한 후 실제 장소 마커·방문 순서·경로를 구현한다. 이동수단은 도보·대중교통·자차만 허용하고, 인접 장소 사이 실제 경로 API의 거리·예상시간을 표시한다. SDK 연결만으로 경로가 검증되지는 않는다.
6. 새 테이블·제약은 기존 `0001_users` 다음 Alembic 리비전에 추가한다. SQLAlchemy 모델, 환경설정, API 계약, 호출부와 테스트를 함께 변경한다.

## 이유와 영향

브라우저 저장은 다른 기기에서 공유되지 않으며 소유권·저장 한도·하트 중복을 서버에서 보장할 수 없다. 서버 저장으로 이를 해결하되 통신·DB 장애를 화면에서 명확히 처리해야 한다. Google Maps로 통일하면 기존 서울 전용 조건과 복수 지도 제공자 분기를 줄일 수 있지만 지역별 장소·경로 지원은 별도 검증해야 한다.

기존 localStorage의 모의 데이터는 자동 업로드하지 않는다. 전환 전 안내하며 이전 자료를 일괄 삭제하지 않는다. 실제 생성·검증 연결 전에는 모의 결과를 확정 저장하거나 임의 선을 실제 경로로 표시하지 않는다. 기존 제품 규칙인 명시적 저장·3개 한도·공개 사본·원본 삭제 cascade는 유지한다.
