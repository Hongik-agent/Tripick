# 00 · 제품 범위와 완료 기준

## 목적

Tripick은 사용자의 여행 조건에 맞는 날짜별 방문 장소와 동선을 제안하고, 사용자가 근거를 확인한 뒤 저장·수정·삭제할 수 있게 한다. 목표 사용자는 국내외 여행을 계획하는 내국인 여행자다. 문서 중심 개발의 범위는 구현에 필요한 결정과 검증을 남기는 것이며 DDD 도입을 뜻하지 않는다.

한 일정에는 현재 화면의 선택 목록에서 여행지 하나를 고른다. 여행지는 도시 또는 지역이며 자유 검색·다중 여행지 일정은 이번 MVP에서 제외한다.

## MVP 목표

| 영역 | 목표 | 상태 |
|---|---|---|
| 조건과 생성 | 필수 시작일·종료일(최대 14일), 인원 구간과 이동수단 등 선택형 조건을 받아 실제 장소·영업시간·경로 근거로 날짜별 일정을 생성. 예산은 이번 MVP에서 제외 | 2026-11-06 사용자 결정 반영, 미구현 |
| 지도 | 국내 네이버지도·카카오맵·Google Maps 선택, 해외 Google Maps로 실제 위치·방문 순서·길찾기 확인 | PRD 목표. 1차 검증은 Google Maps |
| 인증 | Google·Kakao 계정으로 로그인하고 계정별 소유권 확인 | Google은 Supabase Auth와 FastAPI 사용자 저장 경로 구현. Kakao는 공통 API·테이블만 준비 |
| 개인 일정 | 결과를 명시적으로 저장하고 본인 일정만 조회·수정·재저장·삭제 | PRD 목표, 서버 저장 미구현 |
| 저장 한도 | 계정별 활성 저장 일정 최대 3개. 생성·재생성은 개수에 포함하지 않음 | PRD 확정 |
| 커뮤니티 | 저장 일정의 제한된 공개 사본을 게시하고 다른 사용자·기기에서 게시물과 하트를 공유 | 2026-11-04 사용자 결정. 구현 전 공개 데이터·권한 계약 작성 필요 |

저장 전 생성 결과는 읽기 전용이다. 장소·좌표·영업시간·경로·이동시간을 AI가 임의로 지어내지 않는다. 근거가 부족하거나 충돌하면 확정 저장을 막는 것이 현재 PRD의 기준선이다.

## 1차 개발 순서와 제외

2026-10-28 논의에서 백엔드 환경 구성을 먼저 하고 Google Maps로 국내·해외 대표 지역의 지도·장소·영업시간·경로·이동시간을 검증하기로 했다. 국내 지도 3종 선택은 최종 MVP 요구로 유지한다. 날씨, 이력 기반 다음 여행지 추천, 예약·결제, 공동 편집은 현재 MVP 완료 기준에 넣지 않는다. 커뮤니티는 최신 사용자 결정에 따라 기존 PRD의 F09 제외와 달리 포함한다.

## 완료 판단

1. 사용자가 조건을 입력하고 실제 조회 근거가 있는 생성 결과를 확인한다. 조회 실패와 미검증 정보는 성공으로 표시하지 않는다.
2. 인증된 사용자가 결과를 저장하고 다른 기기에서 같은 계정으로 다시 열 수 있다. 서버가 소유권과 저장 최대 3개를 보장한다.
3. 저장 후 편집·재저장·전체 삭제가 가능하며 실패 시 저장 원본을 잃지 않는다.
4. 게시물과 하트가 계정·기기를 넘어 공유되고, 게시·하트 권한 및 중복 하트가 서버에서 검증된다.
5. 정상·오류·권한·동시 저장 시나리오를 검증하고 결과를 기록한다.

이 완료 판단은 목표이며 현재 구현 완료 선언이 아니다. API·데이터 필드와 공급자 지원은 구현 전에 검증·정의해야 한다.
