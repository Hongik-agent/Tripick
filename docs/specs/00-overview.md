# 00 · 제품 범위와 완료 기준

> 2026-11-16 최종 결정: Supabase Auth를 유지하고 OAuth 시작·코드 교환·토큰 관리를 FastAPI BFF로 이전한다. [ADR 0005](../adr/0005-supabase-bff.md)를 따른다. 홈 세계지도 포함, 닉네임 대소문자 구분, 목록 10개, 비용 설정과 현재 구현 상태는 [06 구현·운영](06-implementation.md)을 따른다.
## 목적

Tripick은 사용자의 여행 조건에 맞는 날짜별 방문 장소와 동선을 제안하고, 사용자가 근거를 확인한 뒤 저장·수정·삭제할 수 있게 한다. 목표 사용자는 국내외 여행을 계획하는 내국인 여행자다. 문서 중심 개발의 범위는 구현에 필요한 결정과 검증을 남기는 것이며 DDD 도입을 뜻하지 않는다.

한 일정에는 'AI 일정 생성하기'화면의 여행지 탭에서 여행지 하나를 고른다. 여행지는 도시 또는 지역이며 자유 검색·다중 여행지 일정은 이번 MVP에서 제외한다.

저장 전 생성 결과는 읽기 전용이다. 장소·좌표·영업시간·경로·이동시간을 AI가 임의로 지어내지 않는다. 영업시간 자료가 없으면 해당 방문지에 확인 안내를 붙이고, 휴무나 시간 충돌을 해결할 수 없는 자리는 자유 일정으로 남긴다.

## 1차 개발 순서와 제외

2026-11-15 결정으로 서버 저장·인증·마이그레이션과 모든 여행지의 Google Maps 바탕 표시를 먼저 구성한다. 국내 지도 3종 선택 요구는 Google Maps 단일 제공자로 대체한다. 홈 세계지도는 React Simple Maps와 로컬 world-atlas를 사용한다. OpenAI SDK를 통한 AI 일정 생성 연결 후 실제 장소 마커·방문 순서·경로와 이동시간을 연동·검증한다. 지도 바탕 표시만으로 일정의 장소·경로가 검증됐다고 보지 않는다. 날씨, 이력 기반 다음 여행지 추천, 예약·결제, 공동 편집은 현재 MVP 완료 기준에 넣지 않는다. 커뮤니티는 최신 사용자 결정에 따라 기존 PRD의 F09 제외와 달리 포함한다.

## 저장·인증 원칙

일정·게시물·하트와 인증 토큰을 localStorage에 보관하지 않는다. 브라우저 메모리는 화면 표시와 미저장 입력에만 쓰며, 저장된 데이터는 새로고침·재로그인 시 서버에서 복원한다. 미저장 입력의 새로고침 후 복원은 보장하지 않는다. FastAPI가 입력·세션·소유권을 확인하고 PostgreSQL에 저장한다. 로그인 제공자는 Supabase Auth를 유지하고, 브라우저에는 사용자 ID나 인증 토큰 대신 무작위 세션 식별자를 HttpOnly 쿠키로 전달한다. OAuth 코드 교환과 토큰 저장·갱신은 FastAPI BFF가 담당하며 인증 토큰을 브라우저 JavaScript에 전달하지 않는다.

## 완료 판단

1. 사용자가 조건을 입력하고 실제 조회 근거가 있는 생성 결과를 확인한다. 조회 실패와 미검증 정보는 성공으로 표시하지 않는다.
2. 인증된 사용자가 결과를 저장하고 다른 기기에서 같은 계정으로 다시 열 수 있다. 서버가 소유권과 저장 최대 3개를 보장한다.
3. 저장 후 편집·재저장·전체 삭제가 가능하며 실패 시 저장 원본을 잃지 않는다.
4. 게시물과 하트가 계정·기기를 넘어 공유되고, 게시·하트 권한 및 중복 하트가 서버에서 검증된다.
5. 정상·오류·권한·동시 저장·세션 만료·CSRF·CORS·Alembic 시나리오를 검증하고 결과를 기록한다.
6. 서울 외 국내·해외 모든 선택 여행지의 결과·저장·게시 상세에 해당 지역의 Google Maps가 표시된다. 홈 세계지도는 제외한다.

이 완료 판단은 목표이며 현재 구현 완료 선언이 아니다. API·데이터 필드와 공급자 지원은 구현 전에 검증·정의해야 한다.
