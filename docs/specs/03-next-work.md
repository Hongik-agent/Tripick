# 03 · 다음 작업과 검증

## 다음 구현 단위

1. [API·JSON 계약](04-api.md)의 미정 선택지·제공자 지원을 검증하고 구현 상태를 갱신한다. 커뮤니티 MVP 포함과 예산 제외 결정이 기존 PRD 범위를 바꿨음을 유지한다.
2. Google Maps의 대표 국내·해외 지역에서 장소·영업시간·경로·이동시간을 실제 조회해 지원 범위와 오류 사례를 기록한다. 키는 서버 비밀 설정에 둔다.
3. Google OAuth 후 `PUT /api/users/me`로 사용자 저장을 실제 검증한다. Kakao 제공자를 설정하고 버튼을 연결한 뒤 같은 API로 검증한다. 일정 소유권은 일정 API 구현 시 확립한다.
4. Alembic 마이그레이션으로 개인 일정 저장을 만들고, 활성 3개 한도·재저장·삭제를 서버에서 보장한다. 기존 브라우저 자료가 자동 이전되지 않음을 전환 전에 안내한다.
5. 생성 결과의 근거·검증을 구현하고 프런트엔드의 모의 생성·지도를 실제 데이터로 교체한다.
6. 게시 사본·하트·공개 목록을 서버에 저장하고 프런트엔드의 `localStorage` 커뮤니티를 교체한다.

이는 의존 순서이며 주차·마감 재확정이 아니다. 2026-10-25 PRD의 마감은 2026-11-28이지만, 현재 남은 작업과 인력·외부 API 준비 상태를 반영한 새 일정은 정해지지 않았다.

## 검증 기준

| 시나리오 | 확인할 결과 |
|---|---|
| DB 연결 실패 | `/health`가 503을 반환하고 성공으로 오인하지 않음 |
| 다른 계정의 일정 조회·편집·삭제 | 서버가 거부하고 기존 데이터 유지 |
| 활성 일정 2개에서 동시 신규 저장 2건 | 최대 1건만 성공해 총 3개 유지 |
| 활성 일정 3개에서 재생성·기존 일정 재저장 | 둘 다 허용, 새 일정 저장은 차단 |
| 장소·경로 근거 부족 | 미검증 결과를 확정 저장하지 않음 |
| 다른 브라우저·기기에서 게시·하트 | 같은 서버 데이터와 중복 방지 규칙 확인 |
| 원본 전체 삭제 | 연결된 게시물과 하트가 함께 삭제됨 |
| 개인 일정 수정 | 기존 게시 사본이 자동 변경되지 않음 |
| 공개 게시물 응답 | 정확한 여행 날짜·개인 조건·계정 ID·이메일이 없음 |
| 닉네임 변경 | 기존 게시물에도 새 닉네임이 표시되고 중복 이름은 거부됨 |
| Google·Kakao에서 같은 확인된 이메일 | Supabase가 연결한 사용자 ID 하나로 동일 Tripick 계정을 조회 |
| 커뮤니티 목록 | 하트 수 내림차순 → 게시 시각 오름차순 → ID 오름차순 |

## 2026-11-05 사용자 연결 검증

- 작업 복사본에서 백엔드 인증 단위 테스트 6개 통과. Alembic 오프라인 SQL에서 `users` 생성 확인.
- 프런트엔드 `pnpm exec tsc --noEmit`와 `pnpm build` 통과.
- 대상 PostgreSQL에서 `alembic current`가 `0001_users (head)`를 반환했다. 실제 Google OAuth 완료와 Kakao 로그인은 별도로 확인한다. 일정·커뮤니티 권한과 동시성은 이번 사용자 연결 범위에 포함되지 않는다.
