# 03 · 다음 작업과 검증

> 2026-11-16 최종 결정: Supabase Auth를 유지하고 OAuth 시작·코드 교환·토큰 관리를 FastAPI BFF로 이전한다. [ADR 0005](../adr/0005-supabase-bff.md)를 따른다. 홈 세계지도 포함, 닉네임 대소문자 구분, 목록 10개, 비용 설정과 현재 구현 상태는 [06 구현·운영](06-implementation.md)을 따른다.
## 구현 단계와 후속 작업

아래는 단계별 범위 기록이다. 1~6의 기반은 구현했고 실제 생성·편집 검증은 7의 후속 범위다. 홈 세계지도도 이번 구현에 포함했다.

1. 이번 개정은 명세·ADR 정리다. 이후 코드 변경은 `App.tsx`, `community.tsx`, `supabase.ts`, `GoogleSeoulMap.tsx` → `GoogleMap.tsx` 이름 변경, 백엔드 설정·인증·모델·라우트·테스트·환경변수 예제·Alembic에 걸친다. 여행 기간은 2026-11-15 사용자 답변대로 최대 7일로 통일한다. 인원은 `1`, `2`, `3`, `4`, `5_plus`, 이동수단은 도보·대중교통·자차로 맞추고 닉네임의 모든 공백을 금지한다. UI 선택지·API 검증·JSON 예시·fixture를 함께 갱신한다.
2. [BFF 인증 ADR](../adr/0005-supabase-bff.md)에 따라 FastAPI가 Supabase OAuth 시작·코드 교환·토큰 암호화 보관·갱신·로그아웃을 담당한다. 브라우저 인증 localStorage를 제거하고 쿠키·CSRF·만료·로그아웃·계정 복원을 검증한다. 기존 사용자는 전환 시 재로그인한다.
3. [테이블 계획](02-design-and-decisions.md)의 서버 인증·일정·커뮤니티 테이블과 닉네임 변경을 후속 Alembic 리비전으로 추가한다. 기존 `users`와 `0001_users`를 보존한다. 개발 DB에서 업그레이드와 제약을 확인한 뒤 API를 연결한다.
4. `config.py`에서 CORS 출처·허용 메서드·헤더 설정을 관리하고 `main.py`에 적용한다. [CORS 계약](05-cors.md)에 맞춰 환경변수 예제와 테스트를 갱신한다. 운영은 프런트엔드·백엔드 별도 서버이며 기존 허용 경로 설정을 통한 통신 성공은 사용자 확인 사항이다. 실제 운영 Origin과 API base URL을 배포 설정에 연결하고, 새 쿠키 인증은 별도로 검증한다.
5. 개인 일정과 커뮤니티를 React → FastAPI → PostgreSQL로 전환한다. `App.tsx`와 `community.tsx`의 localStorage 읽기·쓰기·실패 시 로컬 대체 저장을 제거한다. 서버 성공 응답 이후 UI를 갱신하고 다른 기기에서 같은 계정으로 읽는다. 기존 모의 자료는 자동 이전하지 않으며, 전환 전에 안내하고 원본을 일괄 삭제하지 않는다.
6. `GoogleSeoulMap.tsx`를 `GoogleMap.tsx`로 변경하고 컴포넌트명·import·사용처도 함께 갱신한다. 모든 선택 여행지에 쓸 수 있게 확장해 생성 결과·저장 일정·게시 일정의 지도 바탕을 Google Maps로 통일한다. 홈 세계지도에는 React Simple Maps를 추천하며 별도 작업으로 다룬다. 국내 지도 선택 UI·API의 `naver`·`kakao` 옵션과 값 정의는 유지하되 비활성화한다. UI에는 선택할 수 없는 상태로 표시하고, API는 현재 사용 가능한 지도 값으로 `google`만 허용하며 비활성 값으로 들어온 요청은 거부한다.
7. **후속 — OpenAI SDK 연결 이후**: AI 일정 생성, 실제 장소·영업시간·경로 조회와 검증, 일정 장소 마커·방문 순서·실제 경로 표시 및 편집 후 재계산을 연결한다. 구간별 거리·예상시간은 선택 수단의 실제 경로 API 응답을 사용한다. 3개 보유 시 기존 저장 일정의 재생성만 허용하고 같은 일정 ID로 재저장하는 흐름을 구현한다. `generations`·`drafts`·`edit_drafts`도 이 단계의 후속 마이그레이션에 포함한다. OpenAI SDK만으로 실제 경로를 얻는 것으로 간주하지 않는다.

서버 저장 전환 단계에서는 검증된 초안 fixture로 개발·테스트 환경에서 CRUD·권한·동시성을 검사한다. 실제 생성 공급자가 연결되기 전에는 모의 결과를 운영에서 검증 완료로 표시하거나 확정 저장을 허용하지 않는다. 전체 MVP 완료 판단은 SDK·장소·경로 연동 이후다.

이는 의존 순서이며 주차·마감 재확정이 아니다. 2026-10-25 PRD의 마감은 2026-11-28이지만, 현재 남은 작업과 인력·외부 API 준비 상태를 반영한 새 일정은 정해지지 않았다.

## 검증 기준

| 시나리오 | 확인할 결과 |
|---|---|
| 로그인·재로그인·만료·로그아웃 | 토큰이 localStorage에 없고 폐기된 세션은 서버에서 거부됨 |
| CSRF·CORS | 허용 출처의 쿠키 요청만 통과하고 위조된 쓰기 요청은 차단됨 |
| 서버 저장 실패 | localStorage로 대체 저장하지 않고 입력·원본을 보존함 |
| 모든 여행지의 결과 지도 | 선택 목록 전체의 결과·저장·게시 지도 중심 확인, 홈 제외, 실패 안내 |
| Alembic | 빈 DB 및 기존 users DB에서 upgrade 검증, FK·unique·cascade·인덱스 확인 |
| DB 연결 실패 | `/health`가 503을 반환하고 성공으로 오인하지 않음 |
| 다른 계정의 일정 조회·편집·삭제 | 서버가 거부하고 기존 데이터 유지 |
| 활성 일정 2개에서 동시 신규 저장 2건 | 최대 1건만 성공해 총 3개 유지 |
| 활성 일정 3개에서 신규 생성·미저장 결과 재생성 | 서버가 유료 호출 전에 409로 차단 |
| 활성 일정 3개에서 기존 저장 일정 재생성·재저장 | 본인 일정만 허용. 같은 ID·슬롯을 유지하고 재생성 실패·취소·충돌 시 원본 보존 |
| 재생성 초안의 신규 저장·다른 일정 적용·삭제된 대상 적용 | 서버가 거부하고 원본·슬롯 보존 |
| 인원·이동수단 선택 | 1·2·3·4·5_plus 및 walking·transit·driving만 허용 |
| 공개 닉네임 공백 | 앞뒤·중간 공백·탭·줄바꿈을 거부, 자동 삭제하지 않음 |
| 구간별 소요시간 | 실제 경로 거리·예상시간과 조회 조건 확인. 거리 ÷ 고정 속도 대체 금지 |
| 장소·경로 근거 부족 | 미검증 결과를 확정 저장하지 않음 |
| 다른 브라우저·기기에서 게시·하트 | 같은 서버 데이터와 중복 방지 규칙 확인 |
| 원본 전체 삭제 | 연결된 게시물과 하트가 함께 삭제됨 |
| 개인 일정 수정 | 기존 게시 사본이 자동 변경되지 않음 |
| 공개 게시물 응답 | 정확한 여행 날짜·개인 조건·계정 ID·이메일이 없음 |
| 닉네임 변경 | 기존 게시물에도 새 닉네임이 표시되고 중복 이름은 거부됨 |
| Google·Kakao에서 같은 확인된 이메일 | Supabase가 연결한 사용자 ID 하나로 동일 Tripick 계정을 조회 |
| 커뮤니티 목록 | 하트 수 내림차순 → 게시 시각 오름차순 → ID 오름차순 |

## 2026-11-05 사용자 연결 검증

- 작업 복사본에서 백엔드 인증 단위 테스트 6개 통과. Alembic 오프라인 SQL에서 `users` 생성 확인.
- 프런트엔드 `pnpm exec tsc --noEmit`와 `pnpm build` 통과.
- 대상 PostgreSQL에서 `alembic current`가 `0001_users (head)`를 반환했다. 실제 Google OAuth 완료와 Kakao 로그인은 별도로 확인한다. 일정·커뮤니티 권한과 동시성은 이번 사용자 연결 범위에 포함되지 않는다.

## 마이그레이션 검증과 배포

- `alembic upgrade head --sql`이 DB 자격증명 없이 SQL을 생성할 수 있도록 현재 오프라인 경로를 유지한다.
- 분리된 개발 DB에서 `alembic upgrade head` 후 `alembic current`와 실제 스키마를 확인한다. 빈 DB와 `0001_users` 적용 DB를 모두 검사한다.
- 3개 한도·하트 중복·원본 삭제 cascade·버전 충돌은 실제 PostgreSQL 트랜잭션으로 검사한다.
- downgrade 검증은 폐기 가능한 DB에서 수행한다. 운영 테이블 삭제·데이터 손실을 동반한 downgrade를 자동 실행하지 않는다. 운영 적용 전 백업·복원 절차를 확인한다.
- 위 과거 검증 결과는 새 인증·저장·지도·CORS·마이그레이션이 검증됐다는 증거로 사용하지 않는다.
