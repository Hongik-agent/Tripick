# Tripick

React + TypeScript + Vite + Tailwind CSS로 만든 한국어 여행 일정 프로토타입입니다.

## 모의 커뮤니티 게시·하트

**현재는 백엔드 없는 모의 기능입니다. 실제 다른 사용자·기기·브라우저와 공유되지 않습니다.**
Google 로그인은 Supabase Auth로 동작하고 FastAPI의 사용자 저장 API에 연결됩니다. Kakao 로그인 버튼, AI 일정 생성 및 내장 지도는 아직 구현되지 않았습니다.

### 사용 방법

1. Google 계정으로 로그인합니다.
2. 조건을 선택해 일정을 생성하고 내 일정에 저장합니다.
3. 저장한 일정 상세에서 **일정 게시하기**를 누릅니다.
4. 홈의 **여행자들의 인기 일정**에 게시물이 표시됩니다.
5. 게시 카드를 열면 읽기 전용 상세를 볼 수 있습니다.
6. 로그인 후 하트를 보내거나 취소할 수 있습니다.
7. 같은 브라우저에서 로그아웃 후 다른 Google 계정으로 로그인하면 다른 사용자처럼 체험할 수 있습니다.

### 규칙

- 정렬: **하트 수 내림차순 → 게시 시각 오름차순**.
- 하트와 게시 시각까지 같은 경우 게시물 ID 오름차순으로 고정합니다.
- 계정당 게시물 하나에 하트 하나이며, 다시 누르면 취소됩니다.
- 본인 게시물에도 하트를 보낼 수 있습니다.
- 게시물 조회는 비로그인 상태에서도 가능합니다. 게시·하트는 Google 로그인이 필요하지만 데이터는 아직 브라우저에만 저장됩니다.
- 생성 중인 일정이나 저장 전 결과는 게시할 수 없습니다.
- 같은 계정의 같은 저장 일정은 중복 게시되지 않습니다.
- 게시 시 일정의 사본을 저장합니다. 이후 개인 일정 편집은 게시물에 자동 반영되지 않습니다.
- 수정 내용을 게시하려면 게시 취소 후 다시 게시합니다. 새 게시 시각으로 등록되며 하트는 초기화됩니다.
- 게시 취소에는 확인 절차가 있으며, 개인 저장 일정은 유지됩니다.
- 원본 개인 일정을 전체 삭제하면 해당 계정의 게시물·하트도 함께 삭제됩니다.
- 게시물은 개인 일정의 최대 3개 저장 슬롯과 별도입니다.
- 임의 게시물·가짜 하트 수로 채우지 않으며 최초에는 빈 목록입니다.

### 저장 구조와 한계

- 공개 게시 목록 키: `localStorage["tripick-community-v1"]`
- 개인 일정 키: `localStorage["tripick-" + Supabase 사용자 ID]`
- 게시 데이터: 일정 사본, 원본 일정 ID, 작성 계정, 게시 시각, 하트를 보낸 Supabase 사용자 ID 목록.
- UI 로직: `src/community.tsx`, 생성·게시·개인 일정 연결: `src/App.tsx`.
- 계정 식별에는 Supabase 사용자 ID를 쓰지만, 일정·게시물의 소유권은 아직 서버에서 검사하지 않습니다.
- 저장소 삭제 시 데이터가 사라집니다. 개발자 도구로 조작할 수 있으며 권한·부정 하트 방지 기능이 아닙니다.
- 여러 탭의 동시 수정 충돌 처리는 구현하지 않았습니다. 현재 탭 상태 기준으로 저장합니다.
- 개인정보 공개 동의·신고·콘텐츠 검수·운영자 관리 기능은 아직 없습니다.

## 실제 공유 기능으로 전환할 때

1. 현재 Google 로그인·사용자 저장 경로를 기반으로 일정·게시물 API를 구현합니다. Supabase 브라우저 세션은 유지합니다.
2. `users`, `saved-trips`, `published-trips`, `likes` 모델을 구성합니다.
3. 작성자 ID는 클라이언트 입력이 아닌 서버가 검증한 Supabase 사용자 ID에서 가져옵니다.
4. 게시·게시 취소·삭제는 소유자만 허용하고 공개 조회에는 필요한 필드만 반환합니다.
5. 하트는 `(사용자 ID, 게시물 ID)`의 유일성 제약과 트랜잭션으로 중복·경합을 방지합니다.
6. 서버에서 하트 개수와 게시 시각을 계산하고 같은 정렬 규칙으로 페이지네이션합니다.
7. 개인정보 제외·공개 동의·신고/차단·검수·요청 제한과 운영 정책을 마련합니다.
8. `localStorage` 호출을 서버 API로 교체하고 다중 기기·사용자·동시 요청 테스트를 추가합니다.
